## Prerequisites this machine needed beyond the README

Ubuntu 22.04 needs two steps the README does not mention. Without them
`install.sh` stops at step 1 and, past it, ydotoold cannot open `/dev/uinput`
— the daemon transcribes and nothing is ever pasted.

1. **ydotool 1.x is not packaged.** Jammy ships 0.1.8-3, which contains only
   `/usr/bin/ydotool`: no `ydotoold`, no systemd unit, so `install.sh` exits at
   step 1 and step 6 would have no unit to enable. Built 1.0.4 from source —
   pure C over uinput, no libevdev, and `scdoc` needed solely for the man pages
   — with the binaries in `/usr/local/bin` and the unit in
   `/usr/local/lib/systemd/user`, which is on systemd's search path and does
   not collide with a future apt package.

2. **The `input` group alone is not enough.** `/dev/uinput` is `root:root 0600`
   and no udev rule ships for it, so ydotoold fails with `failed to open
   uinput device: Permission denied` even after the reboot. What is missing:

   ```
   KERNEL=="uinput", GROUP="input", MODE="0660", OPTIONS+="static_node=uinput"
   ```

   `uinput` is built into the Ubuntu kernel here, so `lsmod` shows nothing —
   expected, not a missing module.

Three notes on the bench itself, from this run:

- `load_s` includes the model download on a cold cache: `medium` is 1.5 GB and
  took about 25 minutes here. The models were pre-fetched, so the load times
  above measure loading and not downloading.
- The interactive recording needs a TTY (two `input()` calls), so the passage
  was recorded with `parecord` separately, trimmed of silence, and fed through
  `--wav`. There is no `--record-seconds` for a scripted run.
- On a machine with no card the console prints `peak VRAM None MiB`; the
  report itself correctly writes `—`.
